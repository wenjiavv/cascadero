# 使者与城邦 (Hex Envoy)

**[English → README.md](README.md)**

一个单 HTML 文件的六角轨道桌游，加上为了把它下好而搭起来的整套 AI：可调权重的启发式机器人、
推演搜索、自对弈产数据、学习式估值网络，以及一套配对对照评测框架。本文里每一个数字都出自这套框架。

规则是对《Cascadero》（Reiner Knizia 设计，Bitewing Games 出版）的粉丝复刻。本项目非官方、
非商业，美术和界面全部原创，重点在 AI。详见 [法律声明](#法律声明) 与 [NOTICE.md](NOTICE.md)。

## 仓库里有什么

| 部分 | 位置 | 作用 |
|---|---|---|
| 游戏 + 引擎 + AI | `index.html` | 全部在浏览器里跑：规则引擎、三档 AI、动效、撤销、本地对局记录。无需构建。 |
| AI 研究工具 | `online/*.js`、`online/*.py` | 引擎抽取、配对对照、跨引擎对照、模拟器差分测试、自对弈采样、估值网络训练、爬山调参、诊断。 |
| 多核机自对弈调参 | `selfplay/` | 产出当前启发式权重的爬山调参器与终验脚本（2.67 万局）。 |
| 数据集与模型 | `data/`、`online/valuenet.json`、GitHub Releases | 3.2 万局自对弈特征样本（JSONL）和已训练的估值网络。 |
| 自托管私人牌桌 | `online/server.js` | 邀请制 WebSocket 服务器，几个朋友远程用同一引擎对局。不是公开服务。 |

## 快速开始

本地游玩（单人对电脑，或 2–4 人同屏）：

```bash
python3 serve.py 5235        # 打开 http://localhost:5235/
```

跑 AI 工具（Node 18+，在 22/25 上测过）：

```bash
cd online
python3 build-engine.py      # 从 index.html 抽出引擎生成 engine.js（CommonJS）
node simcheck.js 5 back      # 差分测试：正式引擎 vs AI 的一步模拟器
PAIRED=1 node duel.js 80 '{}' '{"burnP":0}' 3 out.json back   # 配对对照：默认权重 vs 覆盖值
```

训练估值网络（Python 3 + numpy）：

```bash
cd online
gunzip -k ../data/sample-selfplay-91d.jsonl.gz
python3 train.py ../data/sample-selfplay-91d.jsonl --hidden 64 --epochs 30 --winK 14 --out valuenet.json
python3 embed-net.py valuenet.json && python3 build-engine.py   # 嵌进 index.html 并重生成 engine.js
```

## 一段话讲清游戏

2–4 人在六角地图上放使者。使者让一个群首次接触某色城镇就在该色成功轨上计分（首位到访拿大奖），
可能顺手取印章、触发连锁推进或额外回合，使者棋落在哪座城镇哪里就加成。六项独特成就和五项双城成就
各只结算一次。谁先到 50 分就触发终局，但只有自己颜色的方块爬到轨顶才有**获胜资格**，否则按小胜规则
比分数。版图背面把一部分田野换成农夫格，24 块面朝下的板块（2 分×5、3 分×5、推进×5、额外回合×4、
移使者棋×5）在你贴着它建造后解锁。

已实现：全部核心规则与农夫板。未实现：双使者棋高级变体、一次落子触发多城时自选计分顺序。

## AI

### 三档

| 档位 | 搜索 | 耗时（M 系列 Mac，背面板） |
|---|---|---|
| 简单 | 静态估值一步贪心 | 即时 |
| 普通 | 筛 5 候选，各 1 次多回合推演 | 约 0.13 秒/手 |
| 困难 | 筛 8 候选，各 2 次推演，卡位价值，终局精算（`endRoll`），估值网络做推演叶子和候选排序 | 约 0.37 秒/手 |

实测：普通对简单 77%，困难对普通 70%（浏览器对局，换座）。

### 静态估值

`simEval()` 把候选落子应用到克隆状态上（含印章、连锁推进、成就、农夫板块，与正式引擎保持一致），
再用 `BOT_TUNE` 里约 28 个权重打分。按版图覆盖在 `BOT_TUNE_BOARD`，按玩家覆盖在 `player.tune`，
由 `tuneOf()` 合并。最重要的几个权重全是自对弈找出来的，不是手调的：

* `sealGainW 4.28`、`chainSealW 5.46`：抢印章，尤其是靠连锁推进抢印章，是最强信号。
* `firstGiftP 0.73`：把首位到访奖励送给对手的惩罚。
* 仅背面板：`burnP 1.5`、`openP 0.75`、`nearW 0.25`。单枚使者贴城不计分会把那座城对这个群
  永久"烧掉"（回放 16 局真人对局：AI 的单枚落子 232/232 都贴了城，烧掉的城 90% 再没拿到分；真人 106/128，但其中 54 次带着印章）。`farmerNearW 0.6`
  奖励为下一手解锁农夫格。
* `heraldW 0`：有了推演之后，显式的使者棋加分反而有害。

### 学习式估值网络

* 特征：`stateFeatures(st, pi, rich)` = 76 维基础 + 12 维战术（我方/对手下一手最好与次好一步、
  可取印章、可完成的成就分、好步数量、使者数差、末手奇偶）+ 3 维行动顺序 + 1 维座次 = **92 维**。
  旧模型按 `n.features` 自动截断。
* 模型：numpy MLP 92→64→1 ReLU，样本为每回合两个视角（行动方、最强对手）的（特征，终局分差）。
  目标 = 分差 + 14×(胜 +1 / 负 −1)（`--winK 14`），把获胜资格规则学进去。
* 两个接入点，都可按玩家开关：`useNet` 用网络替代推演叶子值；`netRankW` 在候选筛选时加入网络意见
  （只评估静态分前 40 名，约 0.4 秒/手）。
* 训练与推理共用同一个特征函数，因为 `engine.js` 是从 `index.html` 生成的。权重以 `VALUE_NET`
  嵌在页面里，同时存于 `online/valuenet.json`。

留出局验证 R²：手写潜力函数 0.29 → 76 维线性 0.43 → 富特征 0.52。加非线性或加数据几乎不动：
**瓶颈在特征，不在数据量。**

`tune.js`（爬山）/ `diag-stuck.js`（定向诊断）。

### 评测方法（最值得抄走的部分）

* **配对赛**（`PAIRED=1`）：每两局同农夫板块布局、同起手、同版图与使者棋，A、B 互换座位。报告
  配对分差和的均值 ± 标准误与配对胜场。40 对的标准误约 2.4 分，比单纯数胜负省一半样本。颜色、
  使者棋、先手各自独立轮换（`pairIdx % 6`、`/6 % 3`、`/18 % 2`）。
* **接受判据**：36–72 对筛方向，独立的 100–400 对终验。胜率为主，分差为辅，因为资格类改动是用分数换胜局。
* **一定跑 A/A 对照。** 我们的对照组 35:37、+1.3 ± 1.9，这才能确认赛制无偏。
* **给模拟器做差分测试。** `simcheck.js` 用正式引擎下棋，逐手核对 `simEval()` 预测的状态是否
  完全一致。两轮独立审查找出十处模拟器/引擎不一致；修掉它们（模型不变）是整个项目最大的一次增益。

### 结果时间线（困难档，未注明即背面板）

| 改动 | 测试 | 结果 |
|---|---|---|
| 启发式权重自对弈爬山（`selfplay/tuner.py`，2.67 万局） | 200 局对旧默认 | 64.5% |
| 烧城惩罚（`burnP/openP/nearW`） | 200 局换座 | 77.5%，每局 +10.2 分 |
| `farmerNearW 0.6` | 100 对 | +9.45 ± 1.44，76/100 对 |
| 估值网络做推演叶子（76 维） | 100 对 | +5.7 ± 1.2，66/100 |
| 估值网络参与候选排序（`netRankW`） | 100 对 | +8.1 ± 1.4，69/100 |
| 富特征（88 维） | 100 对 | +10.5 ± 1.4，74/100 |
| 带胜负的目标（`--winK 14`） | 100 对 | 己色到顶率 56% → 82%；"分数领先却无资格"输局 19 → 2；胜率 61.5%，分差 +0.2（中性） |
| 模拟器一致性修复，模型不变 | 40 对，`xduel.js` | **73.8%，+20.3 ± 2.1** |
| 第二轮引擎修复（推演中的回合状态、同分判定、移子后成就扫描） | 40 对 | 60%，+2.9 ± 2.0 |
| 现版 vs 模拟器修复前的版本 | 40 对 | 87.5%，+23.5 ± 2.1，38/40 |
| 四倍推演预算（`rollN 6, topK 14`）vs 现版 | 40 对 | 75%，+6.0 ± 1.8 → 搜索侧仍有空间 |
| 多人局核对：新版 vs 旧版 | 3 人局 13/13 组，4 人局 20/20 组 | 全胜 |

正面板：烧城惩罚在那里是*负*收益（198 格里 36 城，95% 的格子贴城，城镇不稀缺），正面板保持原权重。

### 无效的尝试（代码保留，默认关闭）

* `achW` 成就趋近加分：0.2/0.5/1/2 → 44/39/39/34%，单调变差。
* `advReply` 推演内对抗式首步回应：+0.3 到 +3.7 ± 2.4，耗时 +40%。
* `endExact` 极小极大/paranoid 终局：−0.7 到 −4.3 ± 2.0。真实对手是贪心的，随机推演比最坏假设更贴近它。
* `cubeLook` 永远不触发：两块版图没有任何格子同时贴两座城，几何核实过。
* `netFinalW`、`netSearchW`（网络做 2 层对抗搜索）：≤ +1.8。
* 同特征再训练（v3）、单独加大 `rollN/topK`、网络接入后的 94 个爬山候选：0 接受。
* 脱离"卡在禁行格下的 10"的静态加分（`stuckTakeW/stuckPlanW`）：只在资格与分数之间挪，不提高胜率。
* `qualLeafW`、`winK 8`、`winK 20`、用修复后数据重训（+2.3 ± 1.2，1.9σ，未接受）。

### 教训

1. ≤16 局全是噪音。用 ≥40–50 局换座，或配对赛。光先手/配色偏差就有 60% 左右。
2. 手写的"显然正确"估值项，多数是净负贡献。
3. 先修模拟器再调搜索。一致性修复之前所有"搜索无效"的结论都建立在有偏模拟器上，后来全部重测。
4. 训练目标必须包含获胜条件，不能只回归分差。资格类改动看胜率，别看分差。
5. 特征比数据量重要；非线性增益很小。
6. 常量特征 std = 0 → 归一化后 NaN → 候选顺序随机。要兜底（`train.py` 置底，`valueNet()` 回退）。
7. A/B 测试双方各用各的模型（`tune.net`）；全局覆盖会让两边一样，测试就没意义了。
8. 爬山 29/50 胜就接受，伪接受率约 16%；要靠多候选 200 局终验收割，别信爬山本身。
9. 给某个场景加启发式之前，先确认场景真的存在（回放或几何）。

### 路线图

1. 统一裁判、记录种子与版本的交叉赛程、最小对手池与真人对局回归集（让防守可测）。
2. 诊断：120 个冻结局面查候选遗漏，100–200 个决策点查次级决策（▲ 选轨、移子、使者棋），50–100 个微型残局。
3. 根节点同预算 Sequential Halving（8 候选 × 48 次续演：8×2→4×4→2×8 对照 8×6），再搜索次级决策。
4. 多头估值（P(胜)、资格、分差）与 300–500 局面的动作排序标签。
5. 正面板走同一套流程（预计 +5–8 分）。
6. 多人局表示重做：描述所有座位与各自的夺冠概率。

## 数据集与模型

自对弈样本为 JSONL，每行一个（回合，视角）：
`{"f": [特征], "y": 终局分差, "w": 是否胜, "q"/"qo": 我方/对手是否到顶, "t": 回合, "g": 局号, "tot": 总回合}`。

| 资产 | 局数 | 行数 | 维度 | 产生方式 |
|---|---|---|---|---|
| `data/sample-selfplay-91d.jsonl.gz`（仓库内） | 300 | 3.5 万 | 91 | 模拟器修复后的引擎，单 worker |
| `selfplay-76d-basic-15657games.tar.gz`（Release） | 15,657 | 186 万 | 76 | 基础启发式机器人与第一版网络 |
| `selfplay-88d-rich-5400games.tar.gz`（Release） | 5,400 | 64.2 万 | 88 | 完整机器人，富特征 |
| `selfplay-88d-rich-qual-5400games.tar.gz`（Release） | 5,400 | 64.2 万 | 88 + q/qo | 完整机器人，带资格标记 |
| `selfplay-91d-simfix-5400games.tar.gz`（Release） | 5,400 | 63.7 万 | 91 + q/qo | 模拟器修复之后 |
| `online/valuenet.json` | – | – | 88（引擎把 92 维特征截断后使用） | 线上部署的模型（`mix14`，带胜负目标） |

有偏模拟器产的数据仍然有用：线上模型就是在它们上训练的，修复后照样好用，这本身就是一个数据点
（模型对偏差不敏感，搜索才敏感）。

## 自托管私人牌桌

`online/server.js` 让几个朋友远程用同一引擎对局。它从设计上就是**私有的**，不是公开游戏站：

* 没有开放注册，没有大厅。开房要房主口令；进房要房间码加配对码（邀请链接把两者都带上）。
  同一 IP 连错五次锁一分钟。
* `CASC_MAX_ROOMS`（默认 8）限制同时存在的房间数。七天无活动的房间自动删除。
* Docker Compose 默认只绑定 `127.0.0.1`；要让外地朋友用，请自行在前面放带 HTTPS 的反向代理（需转发 WebSocket）。
* 服务器权威：客户端只发决策，服务器校验后广播全量状态（含动效事件）。电脑座位在服务器上跑。
  撤销需其他所有真人同意，120 秒超时。
* 保存的数据：`rooms.json`（状态快照，每房 ≤24 份）、`gamelog.jsonl`（只记录有真人参与的局，
  昵称即玩家自填，无账号）、30 天 HMAC 授权 cookie、内存里的 IP 失败计数。不出本机。

```bash
cd online && cp .env.example .env    # 填 CASC_OWNER_PIN / CASC_SITE_PIN
python3 build-engine.py && npm ci --omit=dev
docker compose up -d --build         # http://127.0.0.1:5235/
# 不用 Docker：
CASC_OWNER_PIN=x CASC_SITE_PIN=y PORT=5321 node server.js
```

`deploy.example.sh` 演示 tar 经 ssh 部署到 NAS。`e2e.py` 是 Playwright 回归
（门禁 → 建房 → 邀请链接 → 对局 → 同意制撤销 → 重连 → 坏链接）。

请保持这个用法，不要拿它运营公开或商业服务。
