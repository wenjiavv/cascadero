完成静态审查及内存 Store 的定向复现；未修改文件，未运行需要落盘的原始 smoke/fuzz。

🔴 **会导致错误状态或误导决策**

- **`mcp/src/game.mjs:158`：撤销没有更新恢复快照、没有存盘。** 撤销后尚未完成新回合就重启，会恢复撤销前的局面；终局后撤销则会重新恢复成已结束。已复现内存为第 2 回合、`saved` 和磁盘仍为第 3 回合；应在重启循环前更新 `saved` 并持久化撤销结果。

- **`mcp/src/view.mjs:140`、`:152`：精确预测漏掉无棋子触发的终局。** `exact()` 只跑一次 `runTurn`，而真实循环会立即进入下一次，检查当前玩家是否还有棋子；已复现“最后一枚棋子落在额外回合农夫格”，预测为额外回合、`ends=false`，实际立即终局。模拟后应补结算无需新决策的无棋子终局，再生成结果。

- **`mcp/src/view.mjs:191`：零收益落点被归入“有即时效果”。** `hot()` 用 `scorings.length` 判断，忽略实际推进是否被屏障挡住或已经到顶；已复现蓝轨在 4、落 `0,2` 仅触发一步，默认列表只展示这一个“即时效果”选项，正文却是 `no immediate gain`，并隐藏全部布局招法。应以精确模拟的实际收益及确实触发的可选动作分类。

- **`mcp/data/handbook.en.md:35`、`:71`：50 分终局时点写错。** 引擎在完整结算当前落子后才检查终局（`online/engine.js:529–531`）；已复现达到 51 分后仍需选择连锁推进，并由此让己色轨到顶获得获胜资格。将“立即／达到的瞬间结束”改为“本次落子及所有连锁结算完成后检查”。

- **`mcp/data/handbook.en.md:19`、`mcp/src/view.mjs:220`：把城镇接触描述成永久消耗。** 引擎依据当前连通组和当前邻接占位判断，没有永久访问记录（`online/engine.js:398–400`）；例如正面组 `{8,1; 8,2}` 将 `8,1` 移到 `7,2` 后，再落 `8,1` 可以再次对 `8,0` 计分，且无人邻接时是一步。应将“永远不能再次计分”改成当前组仍有其他棋子接触该城镇时不能计分。

🟠 **边界情况／健壮性**

- **`mcp/src/game.mjs:203`、`:209`：存档可能被截断，失败仍返回成功。** 直接覆盖文件遇到进程中断或写盘失败，会破坏唯一存档；写入异常只打印 stderr，损坏文件随后还会被 `listSaved()` 静默忽略。应使用同目录临时文件加原子替换，并向客户端明确报告保存失败。

- **`mcp/src/game.mjs:172–175`：终局撤销后再次终局会重复记录同一局。** 已复现同一 `id` 在 `gamelog.jsonl` 出现两条完整终局记录，没有撤销或替代标记，供分析脚本使用时可能重复计局或采用废弃结果。应增加修订／替代标记，或明确按局 ID 保留最新有效终局。

- **`mcp/src/engine.mjs:23`：重建失败时静默使用旧引擎。** 当 `index.html` 更新、已有引擎过期，而 Python 缺失或构建失败时，启动仍成功，实际规则版本却没有更新。应拒绝启动，或至少明确输出“正在使用过期引擎”的诊断及失败原因。

- **`mcp/src/index.mjs:29`、`:193–195`：复盘正文直接进入下一局的用户指令。** 保存的任意 Markdown 会原样拼进手册，再作为 `cascadero_play` 的 `role: user` 内容发送；复盘内夹带的行为指令因而与真正的开局指令混在一起。应将复盘作为明确标注的不可信历史资料单独提供，避免直接拼入用户指令正文。

🟢 **可选改进**

- **`mcp/src/index.mjs:24–27`：“最近五份复盘”实际按随机 ID 排序。** 同一天超过五份时，文件名字典序取最后五份不等于保存时间最新，刚写入的复盘可能立刻被排除。应按修改时间排序，或在文件名中加入完整时间戳。

结论：目前不建议交付外部 MCP 客户端使用，应先修复上述 🔴 问题。
